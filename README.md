# Debts Manager

A small offline-first PWA for keeping track of money you owe and money owed to you.

- Add debts in either direction, with an optional due date and note
- Record partial payments (with date and note) and see what's left
- Totals for "owed to me", "I owe" and the net balance
- Overdue / due-soon / settled status, filters, and sorting by due date
- Export and restore a JSON backup
- Works offline and installs to the home screen

All data lives in the browser's IndexedDB on the device; nothing is sent anywhere.

## Development

```sh
npm install
npm run dev      # dev server
npm run build    # production build in dist/ (includes the service worker)
npm run preview  # serve the production build
npm run lint
```

The service worker is generated by [vite-plugin-pwa](https://vite-pwa-org.netlify.app/) at build time, so offline support and install only work with `build` + `preview` (or a deployed build), not in `dev`.

## Install on Android (GitHub Pages)

Android only installs PWAs served over HTTPS, so the app is hosted on GitHub Pages.
`.github/workflows/deploy.yml` builds and publishes it on every push to `main`.

1. Create a repository on GitHub and push this repo to it. On a free account the
   repository has to be public for Pages to work. Only the app's code is published;
   your debts never leave the device.
2. In the repo, go to **Settings → Pages** and set **Source** to *GitHub Actions*.
3. Re-run the workflow if needed (**Actions → Deploy to GitHub Pages → Run workflow**)
   and wait for it to pass. The site is at `https://<user>.github.io/<repo>/`.
4. Open that URL in Chrome on the phone → menu (⋮) → **Add to Home screen → Install**.

Data stays on the phone. Use **Export backup** occasionally, since uninstalling the
app or clearing Chrome's site data deletes it.

## Data model

Each record in the `debts` object store:

```js
{
  id, name, amount, type: "owes_me" | "i_owe", dueDate, note, createdAt,
  payments: [{ id, amount, date, note }]
}
```

Databases from the first version (which kept a single `paid` total) are migrated automatically on first load.
